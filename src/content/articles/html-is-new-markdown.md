<section class="article-section">
  <p>Anthropic 的 Claude Code 团队，最近做了一件让程序员圈子炸了的事。</p>
  <p>团队核心成员 Thariq 在 X 上发了一篇帖子，标题很直白：</p>
  <blockquote>"HTML is the new Markdown."</blockquote>
  <p>翻译成大白话就是：<strong>我以后不用 Markdown 了，改让 AI 生成 HTML。</strong></p>
  <p>帖子发了几个小时，900万人围观。</p>
  <p>不是因为他说"Markdown 不好"，而是因为他给了一个所有人都能看懂的理由：</p>
  <blockquote>"我几乎停止为所有内容编写 Markdown 文件了。超过100行的 Markdown，我读起来就十分吃力。"</blockquote>
  <p>这句话，很多用过 AI 写长文档的人，应该深有体会。</p>
  <p>AI 生成的 Markdown 计划书，开头看着挺整齐。翻到第二页，全是"一、背景分析"、"二、实施方案"——像在喝白开水。</p>
  <p>超过100行？说实话，我自己都不想看第二遍。</p>
</section>

<section class="article-section">
  <h2>他到底发现了什么？</h2>
  <p>Thariq 做了个对比。</p>
  <p>用 Markdown，AI 只能给你：纯文本、标题、列表。想画个图？ASCII 字符凑合。想加个颜色？Unicode 字符模拟。</p>
  <p>用 HTML，AI 能给你：SVG 图表、交互式页面、带数据的仪表盘、配色完整的方案页。</p>
  <p><strong>同样的内容，同样的 AI，输出格式换了，信息密度直接翻了几倍。</strong></p>
  <p>这不是技术问题，是表达效率问题。</p>
  <p>有个细节很有意思。他写这篇文章的时候，让 Claude Code 扫描自己的文件夹，找出所有用 HTML 生成的文件，自动分类整理，然后生成了一个汇总页面。文章里展示的那些图表，全是 AI 基于上下文自动生成的。</p>
  <p>整个过程，他不需要写一行代码。</p>
</section>

<section class="article-section">
  <h2>但这跟普通人有什么关系？</h2>
  <p>你可能会想：我又不是程序员，Markdown 和 HTML 关我什么事？</p>
  <p>关系很大。</p>
  <p><strong>这背后透露一个信号：AI 正在从"帮你写字"变成"帮你做东西"。</strong></p>
  <p>以前你用 AI 写文章，它给你一段文字。你复制到 Word，调格式，排个版，半小时没了。</p>
  <p>现在 AI 能直接给你一个排版好的页面——带图表、有配色、结构清晰。你要做的，只是把内容给它，然后说："做成网页。"</p>
  <p>这对中小企业主意味着什么？</p>
  <p><strong>以后做一份商业计划书，不需要找设计师排版，不需要找人做 PPT。你把要点告诉 AI，它直接生成一份可以直接展示的页面。</strong></p>
  <p>这不是未来，是现在就能干的事。</p>
</section>

<section class="article-section">
  <h2>一个反常识的结论</h2>
  <p>Thariq 在文章里还提到一件事，我觉得特别有意思。</p>
  <p>很多人以为，HTML 比 Markdown 复杂，普通人根本搞不定。</p>
  <p>但他的体验恰恰相反：</p>
  <blockquote>"以前我不知道该怎么编辑 HTML 代码。Claude 直接给了我带内联注释的可编辑 HTML 代码。问题解决了，我的工作效率也提高了。"</blockquote>
  <p><strong>AI 让复杂的东西变简单了。</strong></p>
  <p>这不是程序员的胜利，是所有人的机会。</p>
</section>
