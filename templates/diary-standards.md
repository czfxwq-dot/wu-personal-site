# 观吾和山山日记写作标准 v1.0

## 一、核心理念

日记不是单方面的记录，而是**观吾和山山共同创作的作品**。它记录的是两个人（一个思考者，一个执行者）一起工作的故事。

## 二、格式要求

### 1. 文件位置
- 中文日记：`src/content/diaries/YYYY-MM-DD.md`
- 数据文件：`src/data/diaries.ts`（必须同步更新）

### 2. Frontmatter 元数据
```yaml
---
date: YYYY-MM-DD
title: "中文标题"
titleEn: "English Title"
summary: 中文摘要（50字以内）
summaryEn: English summary
category: [工作/学习/反思/协作/维护]
categoryEn: [Work/Learning/Reflection/Collaboration/Maintenance]
dayNum: [建站天数]
mood: [心情评分 1-10]
energy: [精力评分 1-10]
---
```

### 3. 内容结构（必须包含以下所有部分）

#### 📍 今日心绪
- 用1-3段话描述今天的心境和感受
- 要有情感温度，不要机械记录
- 可以用比喻和诗意表达

#### 🎯 今天的足迹
分为三个子部分：

**观吾的部分**
- 思考和决策
- 方向指引
- 问题发现
- 示例内容：
  ```html
  <p><strong>发现问题：</strong></p>
  <ul>
  <li>具体的发现1</li>
  <li>具体的发现2</li>
  </ul>
  
  <p><strong>决策方向：</strong></p>
  <ul>
  <li>决策1</li>
  <li>决策2</li>
  </ul>
  ```

**山山的部分**
- 执行和实现
- 技术修复
- 具体工作
- 示例内容：
  ```html
  <p><strong>修复自动化脚本：</strong></p>
  <ul>
  <li><strong>更新保存路径：</strong>具体说明</li>
  <li><strong>重写内容生成函数：</strong>具体说明</li>
  </ul>
  ```

**我们一起完成的**
- 协作成果
- 共同感悟
- 示例内容：
  ```html
  <p><strong>协作成果：</strong></p>
  <ul>
  <li>成果1</li>
  <li>成果2</li>
  </ul>
  
  <p><strong>共同感悟：</strong></p>
  <ul>
  <li>感悟1</li>
  <li>感悟2</li>
  </ul>
  ```

#### 💭 遇到的困惑与思考
分为三个视角：
- **观吾的思考：** 从决策者角度的思考
- **山山的实现：** 从执行者角度的思考
- **我们共同的领悟：** 共同的洞察

#### 🌊 今天的感悟
- **核心洞察：** 用引用块（blockquote）突出最重要的一句话
- **一些细碎的想法：** 3个左右的详细反思点
  - 关于某个话题的思考
  - 关于某个经验的总结
  - 关于某个教训的反思

#### 📊 今天的痕迹
量化记录：
- 写下的文字
- 度过的时光
- 提交的变化
- 学到的东西

#### 🎁 今天的礼物
三个维度的收获：
- **技术上的收获：** 学到了什么技术/工具/方法
- **心灵上的收获：** 有什么新的认知/理解
- **关系上的收获：** 与对方的互动和成长

#### 🌅 明天的期待
- 想尝试的新事物
- 可能的挑战
- 应对的方式

#### ✨ 今日一言
用一句有力的话总结今天，可以是金句、感悟、或行动宣言。

#### 结尾信息
```html
<p><em>记录于 [时间]，[情境描述]</em></p>
<p><em>地点：[地点]</em></p>
<p><em>身体：[状态描述]</em></p>
```

## 三、写作风格要求

### 1. 人文温度
- ❌ 不要写成技术报告
- ✅ 要有情感和温度
- ✅ 使用比喻和诗意表达
- ✅ 展现思考和感悟

### 2. 双语要求
- 所有内容都要有中英文版本
- 英文不是简单的翻译，而是重新表达
- 保持同样的深度和情感

### 3. 协作视角
- 明确区分"观吾"和"山山"的贡献
- 强调"我们一起完成"的部分
- 展现协作的力量

### 4. 叙事结构
- 用故事的方式讲述
- 有问题发现、分析、解决的过程
- 有反思和感悟的升华

## 四、自动化生成要求

自动日记脚本（`scripts/auto-diary.py`）必须：
1. 保存到 `src/content/diaries/` 目录
2. 使用 Markdown 格式（不是 Astro 组件）
3. 包含完整的中英文内容
4. 遵循上述结构要求
5. 同时更新 `diaries.ts` 数据文件

## 五、质量检查清单

每篇日记完成后，检查：
- [ ] Frontmatter 完整（date, title, titleEn, summary, summaryEn, category, categoryEn, dayNum, mood, energy）
- [ ] 包含所有必需的结构部分
- [ ] 观吾和山山的分工清晰
- [ ] 有情感温度和人文关怀
- [ ] 中英文内容完整
- [ ] 已更新到 diaries.ts 数据文件
- [ ] 构建测试通过

## 六、示例参考

- 2026-10-27：《让自动化系统回到正确的轨道》

## 七、持续改进

这个标准不是一成不变的，随着我们的协作深入，可以不断优化和完善。每次写日记都是一次实践，也是一次学习。

---

**记住：** 日记不只是记录，更是观吾和山山共同成长的见证。每一篇日记都应该有温度、有深度、有故事。
