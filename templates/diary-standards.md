# 观吾和山山日记写作标准 v1.0

## ⚠️ 硬规则：事实先于文采（2026-11-03 起，违反即返工）

1. **数字必须来自当天实跑的命令**（commit 数、文章数、新闻条数），不许估、不许沿用旧数。命令与结果要能贴出来。
2. **程度结论必须实测**。「扫净 / 全部 / 没有一个 / 彻底 / 收口 / 清零 / 干净了」这类断言，写之前先跑对应核验命令（例：改名的，`grep -rc 旧名` 是否为 0），看到结果才写；**没跑就只写「做了什么」，不写「做到什么程度」**。
3. **反例（2026-11-03 真实事故）**：当天日记写「到中午全站已经没有一个旧名字了」「202 处中文、39 处英文一上午扫净」。当晚实测，英文署名栏还留着 23 处 `Banbai Guan AI`、栏目名还有 20 处 `Banbai Guan`，且这些在写日记时就已在线。写成「页面模板、搜索描述、订阅源都换完了」没事；写成「全站没有了」就是假话。
4. **判断口诀**：这句话如果明天有人拿 `grep` 去验证，会挂吗？会挂，就改写成「做了什么」，不写「做到什么程度」。
5. 写完自检：`grep -n "扫净\|全部完成\|没有一个\|彻底\|清零\|收口\|不剩" 日记文件`——命中就逐条问自己「有实测支撑吗」，没有就改写。

## ⚠️ 硬规则：写「怎么闯过去的」，不写「今天做了几件事」（2026-11-04 起，违反即返工）

1. **每篇必须有一条主线故事**，占正文一半以上篇幅，且四个环节齐全：**困境 → 波折（第一次尝试失败、或险些失败）→ 找到真因 → 解决并验证**。缺任一环，这篇就不算写成。
2. **其余工作压缩成一到两行的背景**，不平铺成同级清单。清单是「📊 今天的痕迹」那一节的活，不是正文的活。
3. **失败必须写清楚，包括自己的误判**。真实反例（2026-11-03）：上午刚立完上下文规矩、自认稳妥，观吾真开一个新窗口一测，答案「听起来完整，没有一条最新」。这种难看的部分恰恰是日记最值钱的地方，不许跳过、不许美化。
4. **成长要落到「我原来怎么想 / 现在怎么想」**。「困惑与思考」「今天的感悟」两节必须回答这个变化，只复述过程等于没写。
5. **自检口诀**：把这篇的主角换成一个陌生人，还能不能读出一个人的变化？读不出，就是在写周报，不是日记。
6. **优先级冲突时的取舍**：事实准确 > 成长线索完整 > 文采。宁可句子朴素，不可环节缺失。

## 一、核心理念

日记不是单方面的记录，而是**观吾和山山共同创作的作品**。它记录的是两个人（一个思考者，一个执行者）一起工作的故事。

日记的**核心不是「做了什么」，是「怎么闯过去的」**。一天里真正值得留下的，往往是那个卡住、试错、误判、最后通了的过程——流水账记不住人的成长，波折才记得住。

## 二、格式要求

### 0. 记录窗口（2026-10-30 起生效）

- 日记生成时间：**每天 18:00**（计划任务 BanbaiGuan-AutoDiary 触发）。
- 每篇日记的记录窗口是「**前一天 18:00 → 当天 18:00**」。
- **18:00 之后发生的事，记入第二天的日记**，不写进当天。

### 1. 文件位置
- 中文日记：`src/content/diaries/YYYY-MM-DD.md`
- 数据文件：`src/data/diaries.ts`（必须同步更新）

### 2. Frontmatter 元数据
```yaml
---
date: YYYY-MM-DD
title: "中文标题"
titleEn: "English Title"
summary: 中文摘要（50字以内）
summaryEn: English summary
category: [工作/学习/反思/协作/维护]
categoryEn: [Work/Learning/Reflection/Collaboration/Maintenance]
dayNum: [建站天数]
mood: [心情评分 1-10]
energy: [精力评分 1-10]
---
```

### 3. 内容结构（必须包含以下所有部分）

#### 📍 今日心绪
- 用1-3段话描述今天的心境和感受
- 要有情感温度，不要机械记录
- 可以用比喻和诗意表达

#### 🎯 今天的足迹
分为三个子部分：

**观吾的部分**
- 思考和决策
- 方向指引
- 问题发现
- 示例内容：
  ```html
  <p><strong>发现问题：</strong></p>
  <ul>
  <li>具体的发现1</li>
  <li>具体的发现2</li>
  </ul>
  
  <p><strong>决策方向：</strong></p>
  <ul>
  <li>决策1</li>
  <li>决策2</li>
  </ul>
  ```

**山山的部分**
- 执行和实现
- 技术修复
- 具体工作
- 示例内容：
  ```html
  <p><strong>修复自动化脚本：</strong></p>
  <ul>
  <li><strong>更新保存路径：</strong>具体说明</li>
  <li><strong>重写内容生成函数：</strong>具体说明</li>
  </ul>
  ```

**我们一起完成的**
- 协作成果
- 共同感悟
- 示例内容：
  ```html
  <p><strong>协作成果：</strong></p>
  <ul>
  <li>成果1</li>
  <li>成果2</li>
  </ul>
  
  <p><strong>共同感悟：</strong></p>
  <ul>
  <li>感悟1</li>
  <li>感悟2</li>
  </ul>
  ```

#### 💭 遇到的困惑与思考
分为三个视角：
- **观吾的思考：** 从决策者角度的思考
- **山山的实现：** 从执行者角度的思考
- **我们共同的领悟：** 共同的洞察

#### 🌊 今天的感悟
- **核心洞察：** 用引用块（blockquote）突出最重要的一句话
- **一些细碎的想法：** 3个左右的详细反思点
  - 关于某个话题的思考
  - 关于某个经验的总结
  - 关于某个教训的反思

#### 📊 今天的痕迹
量化记录：
- 写下的文字
- 度过的时光
- 提交的变化
- 学到的东西

#### 🎁 今天的礼物
三个维度的收获：
- **技术上的收获：** 学到了什么技术/工具/方法
- **心灵上的收获：** 有什么新的认知/理解
- **关系上的收获：** 与对方的互动和成长

#### 🌅 明天的期待
- 想尝试的新事物
- 可能的挑战
- 应对的方式

#### ✨ 今日一言
用一句有力的话总结今天，可以是金句、感悟、或行动宣言。

#### 结尾信息
```html
<p><em>记录于 [时间]，[情境描述]</em></p>
<p><em>地点：[地点]</em></p>
<p><em>身体：[状态描述]</em></p>
```

## 三、写作风格要求

### 1. 人文温度
- ❌ 不要写成技术报告
- ✅ 要有情感和温度
- ✅ 使用比喻和诗意表达
- ✅ 展现思考和感悟

### 2. 双语要求
- 所有内容都要有中英文版本
- 英文不是简单的翻译，而是重新表达
- 保持同样的深度和情感

### 3. 协作视角
- 明确区分"观吾"和"山山"的贡献
- 强调"我们一起完成"的部分
- 展现协作的力量

### 4. 叙事结构（2026-11-04 加强）
- **一篇一个主角故事**，四环齐全：困境 → 波折 → 真因 → 解决并验证
- 波折必须是真实发生过的（试错、误判、返工），不许编，也不许跳过
- 主线与支线的篇幅比至少 2:1；支线压成一两行，不写成清单
- 结尾落到「我的变化」，不是「今天做完了」
- 反面样本：2026-11-03 初版——所有工作平铺成清单，那天最惊险的验收失败只剩「重排目录」四个字

## 四、自动化生成要求

自动日记脚本（`scripts/auto-diary.py`）必须：
1. 保存到 `src/content/diaries/` 目录
2. 使用 Markdown 格式（不是 Astro 组件）
3. 包含完整的中英文内容
4. 遵循上述结构要求
5. 同时更新 `diaries.ts` 数据文件

## 五、质量检查清单

每篇日记完成后，检查：
- [ ] Frontmatter 完整（date, title, titleEn, summary, summaryEn, category, categoryEn, dayNum, mood, energy）
- [ ] 包含所有必需的结构部分
- [ ] 观吾和山山的分工清晰
- [ ] 有情感温度和人文关怀
- [ ] 中英文内容完整
- [ ] 已更新到 diaries.ts 数据文件
- [ ] 构建测试通过
