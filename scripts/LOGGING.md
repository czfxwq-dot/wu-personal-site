# 自动化脚本日志系统说明

## 概述

自动日记和AI新闻采集脚本现在都配备了完整的日志记录系统，方便追踪运行状态和排查问题。

## 日志文件位置

```
scripts/logs/
├── auto-diary-YYYY-MM.log    # 自动日记日志（按月归档）
└── auto-news-YYYY-MM.log     # AI新闻采集日志（按月归档）
```

## 日志级别

- **INFO**: 正常运行信息（启动、步骤、成功）
- **WARNING**: 警告信息（超时、部分失败）
- **ERROR**: 错误信息（完全失败、异常）

## 网络超时处理

AI新闻采集脚本已优化网络超时处理：
- 每个RSS源设置10秒超时
- 超时的源会被记录为WARNING，不会中断整个采集过程
- 即使部分源超时，也能成功采集可用的新闻

## 查看日志

### 实时查看（Windows）

```powershell
# 查看最新的日记日志
Get-Content scripts\logs\auto-diary-2026-10.log -Wait

# 查看最新的新闻日志
Get-Content scripts\logs\auto-news-2026-10.log -Wait
```

### 查看历史记录

```powershell
# 查看所有日志文件
dir scripts\logs\

# 查看特定日期的日志
type scripts\logs\auto-diary-2026-10.log
```

## 故障排查

### 问题1：脚本运行但没有生成内容

**检查步骤：**
1. 查看日志文件，确认脚本是否正常运行
2. 检查是否有ERROR级别的错误信息
3. 确认git提交是否存在（日记脚本依赖当天的git提交）

### 问题2：AI新闻采集失败率高

**可能原因：**
- RSS源不可用或响应慢
- 网络连接问题

**解决方案：**
1. 查看日志中的WARNING信息，确认哪些源超时
2. 可以修改 `auto-news.py` 中的 `RSS_FEEDS` 列表，替换不可用的源
3. 调整 `REQUEST_TIMEOUT` 值（默认10秒）

### 问题3：日志文件过大

**解决方案：**
- 日志按月归档，每月自动生成新文件
- 可以定期删除旧日志文件（建议保留3个月）

## 邮件通知（可选）

脚本支持邮件通知功能，需要在配置中启用：

```python
# 在 auto-diary.py 或 auto-news.py 中配置
NOTIFICATION_ENABLED = True
SMTP_SERVER = "smtp.example.com"
SMTP_PORT = 587
SMTP_USERNAME = "your-email@example.com"
SMTP_PASSWORD = "your-password"
NOTIFICATION_EMAIL = "your-email@example.com"
```

启用后，脚本失败时会自动发送邮件通知。

## 维护建议

1. **定期检查日志**：每周查看一次日志，确认系统正常运行
2. **清理旧日志**：每月清理3个月前的日志文件
3. **监控RSS源**：如果某个源经常超时，考虑替换
4. **备份日志**：重要时期的日志可以备份到其他位置
